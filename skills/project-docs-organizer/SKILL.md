# Project Docs Organizer

Make project documentation findable, trustworthy, and maintainable. The target project owns its information architecture; preserve an explicit location and coherent existing convention.

## Scope and decisions

Inspect the affected reader routes, canonical sources, ownership, lifecycle, metadata, and generator constraints. Inventory the whole documentation system only for a whole-system problem. Reuse an approved structure or migration plan instead of reopening its design.

For a bounded move, merge, deletion, or route repair, explain the issue and intended result in the existing task or handoff. No separate decision artifact or method-card exercise is required. For a material structure choice, compare only viable alternatives and preserve the consequential rationale in the project's existing design process. Ask when authority or a costly-to-reverse choice remains unresolved, not merely because more than one layout is possible; honor delegated choices.

## Invariants

- Give each durable fact one authoritative home and each intended reader a clear route to it. Keep READMEs as orientation rather than copies of topic pages.
- Use one primary grouping axis per level; secondary views belong in navigation, metadata, or local subgroups, not duplicate taxonomies. Create categories only for real content or committed near-term work.
- Delete only with evidence of staleness, duplication, supersession, or migration. Preserve useful unique content and retain history only for a named need.
- Interpret metadata against content and current evidence. Optional flat status/freshness hints are not a universal schema or approval gate; missing metadata is not a blocker.
- Preserve user-selected or generator-owned numbering. Otherwise keep numbering off unless an observed reader need for stable sibling order outweighs path/link churn.
- During moves, merges, and deletions, reconcile active navigation, backlinks, configs, authority references, and copy-paste commands. Date/source volatile external claims or bind them to tested versions. Verify changed routes and the applicable documentation/tool checks.

Report resulting entry points, significant moves/deletions and their evidence, checks, and external links or risks that could not be verified. Do not claim external backlinks were updated without access.
