# Project Docs Organizer

Make project documentation findable, trustworthy, and maintainable.

Inspect the affected reader routes, canonical sources, ownership, lifecycle, and generator constraints. Preserve user-selected locations and coherent project conventions. Scale the inventory to the scope of the reorganization.

Choose structure from actual readers and tasks. Compare viable alternatives when a material choice is unresolved, and retain consequential rationale in the project's existing design process. Use delegated authority; clarify costly or ambiguous decisions where necessary.

Give durable facts an authoritative home and readers a clear route to it. Keep entry points focused on orientation. Use navigation and local subgroups to support secondary views without duplicating content.

Merge or delete material whose useful content is duplicated, stale, superseded, or migrated. Preserve unique information and retain history where it serves an identifiable need. Interpret document metadata alongside current evidence.

Preserve established numbering; introduce ordering where stable sibling order helps readers enough to justify path changes.

Reconcile navigation, backlinks, configuration, authority references, and command examples during moves or deletions. Verify changed routes and applicable checks. Date or version external claims that depend on a changing product.

Report resulting entry points, significant moves/deletions, checks, and unresolved external links or risks.
