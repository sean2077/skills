# Feedback triage

Treat review comments as claims to verify against the current implementation and intended contract. Inspect the trigger, consequence, relevant callers, guards, and tests; a comment may describe a real defect, a fixed issue, a different revision, or a preference.

Apply accepted corrections within the granted editing scope, retaining a regression test or other meaningful verification. Explain disagreements with concrete evidence. Keep unresolved questions visible when requirements or reproduction are insufficient, and identify out-of-scope work separately.

Combine duplicate findings by failure mechanism. Reviewer agreement is supporting context, not a substitute for tracing the claim. Preserve distinct concerns even when they point to the same lines.

Recheck affected findings when the head changes. Report the actual correction and observed verification. Distinguish posting a reply from resolving a review thread, and self-checks from independent review.
