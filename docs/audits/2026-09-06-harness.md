## External research and selective adoption

Primary sources checked on 2026-09-06. These are design inputs, not proof of a local speed or accuracy gain:

- [Superpowers](https://github.com/obra/superpowers), especially [receiving review](https://github.com/obra/superpowers/blob/main/skills/receiving-code-review/SKILL.md) and [requesting review](https://github.com/obra/superpowers/blob/main/skills/requesting-code-review/SKILL.md): adopt technical verification of feedback and bounded review context; do not import obligatory workflow phases or reviewer quotas.
- [Matt Pocock's skills](https://github.com/mattpocock/skills): retain small reusable capabilities and distinguish orchestrating a task from performing a discipline. Do not create new public handoff/feedback routes without evidence that separate discovery helps.
- [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): use on-demand context and compact evidence returns. Do not equate a shorter prompt with measured task improvement.
- [Anthropic long-running application harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps): use distinct generation/evaluation responsibilities where needed, without making multi-agent execution mandatory for small work.
- [OpenAI harness engineering](https://openai.com/index/harness-engineering/): keep authority entry points lean and project evidence navigable. Preserve deterministic controls for costly machine-checkable boundaries rather than adding paperwork.
- [Agent Skills best practices](https://agentskills.io/skill-creation/best-practices): keep triggers discriminating, use progressive disclosure, and distinguish format checks from behavioral evaluation.
- [Claude prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) and [cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking): establish cache/whole-call usage semantics. Total tokens are not interchangeable with billed dollars.

## Verification and limits

The new adversarial tests were run before the adapter/verifier fix and exposed the original false-green, accounting, and containment failures. After correction the focused tests pass. Generic catalog/official format checks, generated-runtime parity, existing workflow/hardening tests, and scaffold/installer checks are separate evidence layers; use the final PR check results for the actual platform matrix.

The local environment has no authenticated Claude host. No live model execution, native skill discovery benchmark, or paid A/B run was performed. New manifests specify future real-host probes rather than fabricate successes. Their adapter loads entry-point instructions, not on-demand references or real implementation tools. No numerical end-to-end speed, dollar savings, or accuracy uplift is claimed.

The retained/deferred decisions above are intentional scope boundaries, not claims that the catalog has no possible improvements. After regression and integrated review, closure means no additional confirmed material issue in the inspected scope remains without a disposition; broader behavioral benefits still need matched real-host evidence.
